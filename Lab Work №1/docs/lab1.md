# Лабораторная работа №1  
Тема: Формулирование требований к программной системе  
Цель работы: Научиться анализировать поставленную задачу, формулировать функциональные и нефункциональные требования к проектируемой системе.

## Перечень заинтересованных лиц (стейкхолдеров)

1. **Сотрудник территориального органа** – должностное лицо (например, ответственный за формирование статистической отчётности), которое подписывает и отправляет пакеты данных в центральную систему.
2. **Ответственный сотрудник вышестоящего органа** – утверждает/согласовывает полученные отчёты, проверяет юридическую значимость подписей.
3. **Сотрудник службы информационной безопасности** – проводит аудит, проверяет корректность проверки подписей, готовит доказательную базу.
4. **Администратор/разработчик интеграционной платформы** – настраивает и мониторит работу сервиса верификации, смотрит логи и метрики.
5. **Сотрудник технической поддержки** – получает уведомления об ошибках проверки подписей, разбирает инциденты.
6. **Представитель внешней информационной системы** – автоматически обменивается пакетами данных с нашей системой.

## Перечень сделанных предположений

1. В одном zip-архиве может быть один оригинальный файл и несколько соответствующих .sig-файлов.
2. Все подписи в архиве — отсоединённые (detached), присоединённые подписи не поддерживаются.
3. Для проверки используется только утилита cryptcp (КриптоПро CSP), библиотека CryptoAPI/.NET не используется.
4. Проверка CRL выполняется автоматически cryptcp (без отдельной реализации).
5. Архив считается успешно проверенным, только если ВСЕ подписи, указанные в манифесте, валидны.
6. Входное сообщение в Kafka содержит только ссылку на архив в S3 и идентификатор операции (дополнительные метаданные не требуются).
7. В случае любой ошибки проверки архив НЕ перемещается в «проверенный» бакет.
8. Размер одного архива — до 100 МБ.

## Перечень нефункциональных требований (повышенная сложность)

| ID        | Требование                                                                                                         | Обоснование и приоритет                                      |
|-----------|--------------------------------------------------------------------------------------------------------------------|--------------------------------------------------------------|
| NFR-01    | Время обработки одного архива — не более 7 секунд                                                                  | Критично для конвейера обработки документов                  |
| NFR-02    | Доступность сервиса — не менее 99,9 % за месяц                                                                     | Юридически значимые операции не терпят длительных простоев   |
| NFR-03    | Все действия с подписями и отчеты должны храниться не менее 6 лет                                                  | Требования 63-ФЗ и внутренние политики компании              |
| NFR-04    | Полная прослеживаемость: каждый запрос должен иметь уникальный ID, сохраняемый во всех логах и БД                  | Необходимость доказательной базы в суде                      |
| NFR-05    | Корректность проверки подписей должна соответствовать результатам утилиты cryptcp КриптоПро CSP (100 % совпадение) | Гарантия юридической значимости проверенных документов       |
